# Prime app: menu bar control panel

Date: 2026-11-08, third session. macOS 26, Swift 6.4.2.

## Verified

- `Spacedock install` wrote `~/Applications/Spacedock.app` with `LSUIElement=true`, `SpacedockRole=prime`, bundle id `dev.lubelski.spacedock`. `lsappinfo` reports `type="UIElement"`. No Dock tile.
- `open ~/Applications/Spacedock.app --args --panel` opened the control panel. Screenshot (by window id) shows three projects, the running one marked "running" with a "Show" button, the others "Launch". Running state comes from `NSRunningApplication.runningApplications(withBundleIdentifier:)`.
- The panel's first appearance was at X = -647, on the external display, while the user worked on the built-in display. `NSWindow.center()` on a windowless accessory app does not pick `NSScreen.main`. Fixed by positioning from `NSScreen.main.visibleFrame`.

## Not yet verified

- Menu bar menu contents and the running swatch. `osascript` could not click the status item: "osascript is not allowed assistive access". Needs the user to click, or Accessibility permission for the terminal.
- Activating a running project app from the menu switches to its Space. Depends on the Mission Control setting "When switching to an application, switch to a Space with open windows".
- Restart (quit, wait, regenerate, relaunch) end to end.
- Add form, settings save, remove.

## Inference

Running state through `NSWorkspace` launch and terminate notifications is enough for a menu that rebuilds on open and a panel that refreshes on demand. A file watcher on `projects.json` is not needed while the menu reloads the registry each time it opens.

## Restart (verified later the same day)

`Spacedock restart` with Hoard and the prime app running: both quit through the Apple event, 4 bundles regenerated, both relaunched with new pids. 0.93 s wall clock. The CLI waits for `NSRunningApplication.isTerminated` by spinning `RunLoop.current` in 50 ms steps, up to 3 s, then `forceTerminate`.
